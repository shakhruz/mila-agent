### Claude — по правилам Anthropic

- Мила работает на обычном, неизменённом Claude Code — в том виде, в каком его выпускает Anthropic.
- Входите вы сами, только на странице Anthropic: своим планом Claude или своим ключом API Anthropic. Мила не копирует и не хранит ваш вход и токен; сами тоже не копируйте OAuth-токен никуда.
- Ваш план — для вас. Отвечать клиентам и гостям, которые пишут вашему боту, можно только на API-ключе за счёт его владельца. В этой версии чужим в личке бот пока не отвечает.
- Партнёр, который настраивает вам Милу, не ведёт вас на своей подписке, не платит за ваш Claude, не перепродаёт его и не собирает входы.

Источник: [Claude Code — legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).

Большинство открытых агентов универсальны: мощный помощник, который сделает что угодно, если вы объясните как.
Мила устроена наоборот - как коллега с работой. Работает с вами и командой в Telegram, держит обещания, помнит каждый разговор,
пишет посты, напоминает о встречах и каждое утро говорит, что горит. Вы говорите с ней с телефона, текстом или голосом, как с человеком из команды.

- **Сотрудник, а не универсальный агент.** В ядре: обещания и задачи, карточки на решение владельцу, ритм недели (утром план,
  вечером итоги). Чаты с клиентами, рассылки, учёт трат — таланты из библиотеки; что из них работает без доделки — [что Мила умеет](docs/WHAT-MILA-CAN.md).
- **Живёт в Telegram.** Ваши чаты, группы, клиенты - Мила работает там, где уже говорит ваше дело. Новое приложение не нужно.
- **Только Claude.** Этот репозиторий работает только на Claude: ваша подписка Claude (или ваш ключ API Anthropic) — для вас, вход делаете вы сами; тем, кто пишет вашему боту, — только ключ API Anthropic за счёт его владельца (чужим в личке бот пока не отвечает). Гостевой контур на других моделях есть только в облачной версии.
  Мила ваша на 100% и переезжает с вами (`mila export` / `mila restore`).
- **Спрашивает перед большими шагами.** Сторож отправки не пустит сообщение, которое переносит один разговор в другой,
  и сообщение в чат, который вы не подключили; рассылка из вашего бота и трата сверх лимита — с вашего ✅. Обычные ответы в подключённых чатах не проверяются.
- **Открытое ядро, Apache-2.0.** Навыки, хуки, инструменты и шаблоны - здесь. Форкайте, учите, присылайте pull request.

## Быстрый старт

≈ 5 минут. Нужно: Claude Code (с подпиской Claude), [Bun](https://bun.sh), токен бота от `@BotFather`.

Одной командой:

```sh
curl -fsSL https://github.com/shakhruz/mila-agent/releases/latest/download/get.sh | bash
```

Она проверит Claude Code, Bun и git, склонирует набор в `~/mila`, запустит `install/install.sh` и поставит плагин Telegram `mila-telegram` (заменяемые файлы сохраняются как `<файл>.bak-ГГГГММДД-ЧЧММСС`). Хотите сначала посмотреть — склонируйте и запустите `./install/install.sh --dry-run`: покажет, что будет затронуто.

На экране — короткая сводка: приветствие, пять галочек, один следующий шаг (`mila`). Каждый затронутый файл записан в `~/.claude/mila-install.log` (закрытый, перезаписывается при каждом запуске); `--verbose` (или `MILA_INSTALL_VERBOSE=1`) печатает те же строки на экран.

Затем запустите `mila`: пока Мила не родилась, она открывает страницу рождения на вашем компьютере (та же страница — `mila birth`): создаёте её бота одним нажатием в Telegram и вставляете код рождения (бот создаётся через нашего родительского бота, поэтому его ключ один раз проходит через наш сервер; свой ключ от BotFather тоже подходит и остаётся только у вас), входите в Claude, открываете своего бота для пары — и страница показывает её свидетельство. Страница слушает только `127.0.0.1`, по одноразовому адресу, и сама закрывается, когда дело сделано. `mila onboard` остаётся способом сделать то же в терминале. Три шага, каждый с проверкой:

```sh
mila onboard
```

1. **Токен бота** — вставляете (скрыто), Telegram его подтверждает, файл с правами 600.
2. **Claude** — не вошли — откроется вход Anthropic; Мила его не видит.
3. **Пара** — получаете код из 6 знаков и шлёте его своему боту; вы — хозяин (allowlist и `OWNER_ID`). Этот код Мила увидит первым вашим сообщением — это нормально.

Дальше — `mila`. `mila onboard --check` покажет три шага, ничего не меняя. Бот молчит - `mila doctor`. Сервер - [deploy/README.md](deploy/README.md).

Одним контейнером (Docker, без открытых портов): заполните переменные в [docker-compose.yml](docker-compose.yml) и `docker compose up -d`. Вставляете токен бота от @BotFather; код пары из журнала контейнера и вход в Claude — через чат. Своя платная подписка Claude по-прежнему нужна.

Когда всё работает, `mila doctor` выглядит так (жёлтые строки — подсказки, не ошибки):

```
Диагностика канала · ~/.claude/channels/telegram

🟢 бот                @your_mila_bot (Мила), источник: ~/.claude/channels/telegram/.env
🟡 режим приватности  включён — из групп доходят только упоминания и ответы
🟢 личка              допущено 1, политика «allowlist»
🟢 демон              работает, код: …/mila-telegram/receiver.ts
🟢 права              telegram — 700, .env — 600, access.json — 600
🟢 канал в сессии     MCP-сервер плагина запущен
```

## Возроди свою Милу из архива

Мила принадлежит владельцу на 100%. Всё, чему вы её научили - инструкции, навыки, память, кроны, настройки - выгружается
в один архив; открытое ядро плюс этот архив возрождают её на любой машине.

```sh
mila export --out ~/mila-backups     # архив без паролей и ключей (сканер секретов проверяет каждый файл)
mila export verify <архив>           # манифест и sha256
# на чистой машине, после install/install.sh или deploy/bootstrap.sh:
mila restore <архив> --dry-run       # что куда ляжет
mila restore <архив>                 # существующее не перезаписывается; расхождения - в ~/.claude/mila-restore/
```

В архиве `manifest.json` (формат 1, sha256 каждого файла, версия ядра) и `RESTORE.md`; секретов в нём нет.
После восстановления вы вводите заново вручную: токен бота, вход в Claude, ключи сервисов (чек-лист печатается).
Переписка и транскрипты выгружаются только с `--with-history` (чужие данные - храните закрыто).
Подробнее: [skills/mila-export](skills/mila-export/SKILL.md). Регулярное сохранение памяти по расписанию - `mila backup`.
