# Планировщик — дела вовремя, вне сессии

*English — [SCHEDULER.md](SCHEDULER.md).*

**Что это.** «Напоминай по понедельникам», «проверь через неделю», «пришли сводку в девять» — Мила записывает такое дело в файл у себя дома, а маленькая служба вне сессии Claude Code в нужную минуту приносит его ей обычным событием. Перезапуск сессии, обновление образа или неделя тишины ничего не теряют.

В текстах для людей служба называется «Планировщик» (EN: the Scheduler). Имена файлов и папок состояния сохраняют прежнее имя: `install/baraban.py`, `state/baraban`.

## Почему не таймер самой сессии
Задача, поставленная внутри сессии (`CronCreate`), живёт в сессии: исчезает при перезапуске и сама через 7 дней. Задача Планировщика лежит в `~/work/schedule/jobs.json`, и запускает её процесс, который от сессии не зависит.

## Как поставить задачу
Мила делает это через `skills/raspisanie/mila_cron.py` (навык `raspisanie`):

```bash
M=~/.claude/skills/raspisanie/mila_cron.py
python3 $M next "0 9 * * 1" 3                    # сначала посмотреть ближайшие сроки
python3 $M add otchet-pn "0 9 * * 1" "Понедельник: недельный отчёт хозяину"
python3 $M list                                  # следующий срок, последний запуск, итог
python3 $M done otchet-pn "отправлен, 5 строк"   # итог последнего запуска
python3 $M pause|resume|rm <id>
python3 $M extend <id> ГГГГ-ММ-ДД
```

Хозяин этого не набирает: он говорит в чате «напоминай по понедельникам», Мила ставит задачу и называет ближайший срок.

## Правила
| Правило | Значение |
|---|---|
| Расписание | выражение cron из 5 полей, в часовом поясе хозяина |
| Как часто | не чаще раза в 5 минут |
| Задач в одном доме | не больше 30 |
| Текст задачи | 1–2000 знаков |
| Срок жизни | 30 дней по умолчанию, не больше 90; потом одно событие «продлить?» и тишина. Задач без срока нет: вечная задача тратит подписку молча |
| Чья задача | своя (`by mila`) или по слову хозяина либо администратора — тогда с `--word <чат>/<сообщение>` |

Часовой пояс и тихие часы берутся из `USER.md` хозяина (строки «Часовой пояс — Area/City» и «Тихие часы — 22:00–08:00»); без них — Asia/Tashkent и 22–08.

## Как задача доходит до Милы
Раз в минуту Планировщик делает один проход (`baraban.py tick`). Задача срабатывает, когда её срок новее последнего запуска и новее её создания. Запуск — одна строка, дописанная во входящий журнал плагина Telegram, — тем же путём идут ритуалы и сообщения хозяина; сессия видит:

```
[⏰ расписание] otchet-pn
Понедельник: недельный отчёт хозяину
Сделай и запиши итог: python3 ~/.claude/skills/raspisanie/mila_cron.py done otchet-pn "…"
```

Мила делает дело и записывает итог командой `done`.

- **Пропущенные сроки.** Машина была выключена три срока — Мила получает ОДНО событие, не три (`--catchup one`, по умолчанию). С `--catchup skip` срок старше 5 минут отбрасывается.
- **Тихие часы.** Срок внутри тихих часов хозяина ждёт и срабатывает один раз, когда они кончатся (`--quiet respect`, по умолчанию; `--quiet ignore` — сразу).
- **Не доставлено.** Если событие не удалось записать, запуск не отмечается: следующая минута пробует снова.
- **Срок вышел.** Одно событие «срок задачи вышел — продлить?», дальше тишина до `extend` или `rm`.

## Как за ним смотреть
- `python3 install/baraban.py status --home <дом> [--state <папка>]` — по каждой задаче: последний запуск, пять последних запусков, что ждёт конца тихих часов.
- `<state>/fired.jsonl` — каждый доставленный запуск: время, дом, задача.
- `<state>/watch.jsonl` — задача сработала дважды, а после первого из двух `done` не было: одна строка. Задача, которая срабатывает и не доводится, видна, а не молчит.

## Где он работает
- **Образ контейнера** (`docker/entrypoint.sh`): цикл раз в минуту делает проход для дома в контейнере; состояние в `~/state/baraban`. Настраивать нечего.
- **Сервер с несколькими домами**: таймер машины раз в минуту запускает `baraban.py tick --home <дом> --slug <имя> --owner <id> --state <папка>`, по строке на дом.
- **Ноутбук** (`install/install.sh`): установщик этот таймер не ставит. Пока вы его не добавили, задачи хранятся, но не срабатывают. Хватит одной строки своего планировщика:
  `* * * * * python3 <kit>/install/baraban.py tick --home "$HOME" --owner <ваш Telegram id>`.

## Что бережёт дом
Служба может работать от root над домом, которому не верит. Каждый файл в доме она открывает по одному шагу пути, не проходя по ссылкам, принимает только обычные файлы, журнал только дописывает и никогда не создаёт, а своё состояние держит вне дома — задача не может переписать, когда она срабатывала.
